## LAB1 — EMBEDDED HTTP SERVER
Hardware lab1:

    Мікроконтролер ESP32 (модель ESP32 DevKit v1): Виступає в ролі автономного HTTP-сервера, що обробляє запити та керує доступом до файлової системи.

    Вбудований Wi-Fi модуль: Забезпечує бездротове підключення до локальної мережі (режим Station) для отримання IP-адреси та взаємодії з клієнтами.

    Flash-пам'ять: Використовується для постійного зберігання образу файлової системи з веб-ресурсами.

    Інтерфейс USB: Забезпечує живлення пристрою та можливість моніторингу стану сервера через Serial-порт (115200 baud).

ПЗ та бібліотеки lab1:

    SPIFFS.h: Бібліотека для роботи з застарілою, але надійною файловою системою SPIFFS (Serial Peripheral Interface Flash File System), що дозволяє монтувати розділ Flash-пам'яті та зчитувати файли.

    WiFi.h: Керує стеком TCP/IP та забезпечує аутентифікацію в мережі Wi-Fi за допомогою SSID та пароля.

    WebServer.h: Використовується для створення HTTP-сервера на стандартному порті 80. Дозволяє реєструвати обробники (callback-функції) для конкретних URI, як-от handleRoot для головної сторінки.

    Framework Arduino: Базове середовище розробки, використане для конфігурації периферії та логіки роботи мікроконтролера.

Frontend:

    HTML5 / CSS3: Веб-інтерфейс, розроблений у вигляді файлу index.html, що зберігається у пам'яті контролера. Сторінка має адаптивний дизайн (Viewport meta tag) для коректного відображення на різних пристроях.

    StreamFile: Метод передачі даних, при якому сервер зчитує вміст файлу зі SPIFFS та транслює його безпосередньо у відповідь клієнту з MIME-типом text/html.

    UI Design: Використання сучасних CSS-технологій (Flexbox, Grid Layout) для створення картки моніторингу з темною темою та візуальними бейджами стану системи.


## LAB2 — ASYNC LED CONTROL VIA REST API
Hardware lab2:

    Мікроконтролер ESP32-C3 (WeAct Studio): Виступає в ролі REST-сервера, що обробляє асинхронні HTTP-запити від клієнта.

    Вбудований світлодіод (GPIO 8): Підключений до піна 8, який виступає об'єктом керування (увімкнення/вимкнення).

    Модуль Wi-Fi: Забезпечує бездротовий зв'язок між браузером та контролером для передачі HTTP-пакетів у локальній мережі.

    Flash-пам'ять: Використовується для зберігання образу файлової системи LittleFS, що містить веб-інтерфейс.

ПЗ та бібліотеки lab2:

    LittleFS: Сучасна енергонезалежна файлова система, використана для зберігання файлу index.html. Це дозволяє повністю відокремити фронтенд (HTML/JS) від основної логіки С++ коду.

    WiFi.h: Забезпечує стабільне підключення до мережі та отримання IP-адреси пристрою.

    WebServer.h: Окрім роздачі статичних файлів на порті 80, бібліотека реалізує наступні API-ендпоїнти:

        GET /api/status: Повертає поточний стан світлодіода у форматі JSON.

        POST /api/control: Приймає команди (on/off) для зміни стану піна.

        OPTIONS /api/control: Обробляє Preflight-запити для забезпечення політики CORS.

    ArduinoJson (v6/v7): Використовується для десеріалізації вхідних POST-запитів та формування структурованих JSON-відповідей.

Frontend технології:

    JavaScript (Fetch API): Реалізує асинхронну логіку взаємодії. Браузер надсилає запити до ESP32 у фоновому режимі без перезавантаження всієї сторінки.

    DOM Manipulation: Динамічне оновлення інтерфейсу (зміна кольору "лампочки" та тексту статусу) на основі даних, отриманих від контролера.

    setInterval (Polling): Функція для автоматичного опитування стану пристрою кожні 5 секунд, що забезпечує актуальність відображення інформації, навіть якщо стан було змінено з іншого пристрою.

    CSS3: Використання ефектів box-shadow та transition для створення візуальної симуляції світіння світлодіода.

## LAB3 — REAL-TIME SENSOR MONITORING (WEBSOCKETS)
Hardware lab3:

    Мікроконтролер ESP32-C3 (WeAct Studio): Обчислювальне ядро на базі архітектури RISC-V, що забезпечує одночасну роботу HTTP-сервера та WebSocket-сервера для трансляції даних у реальному часі.

    Датчик освітленості BH1750: Цифровий 16-бітний сенсор (люксметр), що вимірює інтенсивність світла в діапазоні від 1 до 65535 люкс.

    Інтерфейс підключення I2C: Використовуються апаратні піни GPIO 8 (SDA) та GPIO 9 (SCL) для забезпечення стабільного обміну даними між сенсором та контролером.

    Wi-Fi модуль: Інтегрований приймач, що працює в режимі станції (STA) для підключення до локальної мережі та взаємодії з веб-клієнтами.

ПЗ та бібліотеки lab3:

    LittleFS: Енергонезалежна файлова система, що використовується для автономного зберігання файлу index.html у Flash-пам'яті пристрою.

    WebSocketsServer (v2.x): Реалізує повнодуплексний зв’язок на порті 81, що дозволяє контролеру самостійно "штовхати" (push) дані клієнту кожні 500 мс без запиту з боку браузера.

    WebServer.h: Використовується для початкової видачі вебінтерфейсу на стандартному порті 80 через метод streamFile.

    BH1750.h: Бібліотека для ініціалізації датчика та зчитування значень у режимі безперервної високої роздільної здатності (CONTINUOUS_HIGH_RES_MODE).

    ArduinoJson (v6/v7): Використовується для пакування значень освітленості у формат JSON-пакета для передачі через WebSocket.

Frontend технології:

    JavaScript (WebSockets API): Підтримує постійне з’єднання. Через обробник onmessage приймає JSON-пакети, оновлює статистику (Current/Min/Max) та додає нові точки на графік.

    Chart.js (v4.x via CDN): Бібліотека для візуалізації, що рендерить лінійний графік освітленості з апаратним прискоренням.

    Алгоритм Rolling Window: Програмна реалізація динамічного зсуву графіка вліво шляхом видалення застарілих даних (понад 30 точок) для підтримки високої продуктивності системи.

    Адаптивний CSS: Темна тема інтерфейсу з використанням Grid-сітки для коректного відображення на мобільних пристроях та ПК.

LAB4 — WI-FI CAPTIVE PORTAL & NVS STORAGE
Hardware lab4:

    Мікроконтролер ESP32-C3 (WeAct Studio): Виступає в ролі інтелектуального мережевого вузла, що підтримує два режими: Access Point (AP) для конфігурації та Station (STA) для основної роботи.

    Енергонезалежна пам’ять (NVS): Використовується для надійного зберігання облікових даних Wi-Fi (SSID та пароль) навіть після вимкнення живлення пристрою.

    Wi-Fi модуль: Забезпечує створення власної точки доступу з фіксованою IP-адресою 192.168.4.1 для автоматичного доступу до порталу налаштувань.

    USB-інтерфейс: Використовується для живлення та моніторингу процесу підключення через Serial-порт.

ПЗ та Бібліотеки lab4:

    LittleFS: Сучасна файлова система, що використовується для зберігання файлу portal.html, що дозволяє розмежувати логіку сервера та дизайн інтерфейсу користувача.

    Preferences.h: Бібліотека для зручної роботи з NVS-пам'яттю через пари "ключ-значення", що забезпечує збереження налаштувань між перезавантаженнями.

    DNSServer.h: Ключовий компонент для реалізації перехоплення запитів. Він перенаправляє будь-який DNS-запит (*) на IP-адресу контролера, що змушує смартфони автоматично відкривати сторінку налаштувань.

    WebServer.h: Реалізує HTTP-сервер на порті 80, обробляє запити для видачі форми налаштування та прийому нових параметрів через POST-запит.

    WiFi.h: Керує режимами роботи радіомодуля (AP/STA) та процесом аутентифікації в домашній мережі.

Frontend:

    Captive Portal Logic: Реалізовано обробку специфічних системних URI (наприклад, /generate_204), які Android та iOS використовують для автоматичного виявлення точок доступу з авторизацією.

    Modern UI: Веб-сторінка налаштувань розроблена з використанням адаптивного дизайну, що забезпечує зручне введення SSID та пароля на мобільних пристроях.

    Fetch API: Використовується для відправки конфігураційних даних на сервер без перезавантаження сторінки, надаючи користувачеві зворотний зв'язок про успішне збереження.
