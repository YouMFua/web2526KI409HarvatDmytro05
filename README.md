## LAB1 — EMBEDDED HTTP SERVER
Hardware lab1:

    Мікроконтролер ESP32 (модель ESP32 DevKit v1): Виступає в ролі автономного HTTP-сервера, що обробляє запити та керує доступом до файлової системи.

    Вбудований Wi-Fi модуль: Забезпечує бездротове підключення до локальної мережі (режим Station) для отримання IP-адреси та взаємодії з клієнтами.

    Flash-пам'ять: Використовується для постійного зберігання образу файлової системи з веб-ресурсами.

    Інтерфейс USB: Забезпечує живлення пристрою та можливість моніторингу стану сервера через Serial-порт (115200 baud).

ПЗ та бібліотеки lab1:

    SPIFFS.h: Бібліотека для роботи з застарілою, але надійною файловою системою SPIFFS (Serial Peripheral Interface Flash File System), що дозволяє монтувати розділ Flash-пам'яті та зчитувати файли.

    WiFi.h: Керує стеком TCP/IP та забезпечує аутентифікацію в мережі Wi-Fi за допомогою SSID та пароля.

    WebServer.h: Використовується для створення HTTP-сервера на стандартному порті 80. Дозволяє реєструвати обробники (callback-функції) для конкретних URI, як-от handleRoot для головної сторінки.

    Framework Arduino: Базове середовище розробки, використане для конфігурації периферії та логіки роботи мікроконтролера.

Frontend:

    HTML5 / CSS3: Веб-інтерфейс, розроблений у вигляді файлу index.html, що зберігається у пам'яті контролера. Сторінка має адаптивний дизайн (Viewport meta tag) для коректного відображення на різних пристроях.

    StreamFile: Метод передачі даних, при якому сервер зчитує вміст файлу зі SPIFFS та транслює його безпосередньо у відповідь клієнту з MIME-типом text/html.

    UI Design: Використання сучасних CSS-технологій (Flexbox, Grid Layout) для створення картки моніторингу з темною темою та візуальними бейджами стану системи.


## LAB2 — ASYNC LED CONTROL VIA REST API
Hardware lab2:

    Мікроконтролер ESP32-C3 (WeAct Studio): Виступає в ролі REST-сервера, що обробляє асинхронні HTTP-запити від клієнта.

    Вбудований світлодіод (GPIO 8): Підключений до піна 8, який виступає об'єктом керування (увімкнення/вимкнення).

    Модуль Wi-Fi: Забезпечує бездротовий зв'язок між браузером та контролером для передачі HTTP-пакетів у локальній мережі.

    Flash-пам'ять: Використовується для зберігання образу файлової системи LittleFS, що містить веб-інтерфейс.

ПЗ та бібліотеки lab2:

    LittleFS: Сучасна енергонезалежна файлова система, використана для зберігання файлу index.html. Це дозволяє повністю відокремити фронтенд (HTML/JS) від основної логіки С++ коду.

    WiFi.h: Забезпечує стабільне підключення до мережі та отримання IP-адреси пристрою.

    WebServer.h: Окрім роздачі статичних файлів на порті 80, бібліотека реалізує наступні API-ендпоїнти:

        GET /api/status: Повертає поточний стан світлодіода у форматі JSON.

        POST /api/control: Приймає команди (on/off) для зміни стану піна.

        OPTIONS /api/control: Обробляє Preflight-запити для забезпечення політики CORS.

    ArduinoJson (v6/v7): Використовується для десеріалізації вхідних POST-запитів та формування структурованих JSON-відповідей.

Frontend технології:

    JavaScript (Fetch API): Реалізує асинхронну логіку взаємодії. Браузер надсилає запити до ESP32 у фоновому режимі без перезавантаження всієї сторінки.

    DOM Manipulation: Динамічне оновлення інтерфейсу (зміна кольору "лампочки" та тексту статусу) на основі даних, отриманих від контролера.

    setInterval (Polling): Функція для автоматичного опитування стану пристрою кожні 5 секунд, що забезпечує актуальність відображення інформації, навіть якщо стан було змінено з іншого пристрою.

    CSS3: Використання ефектів box-shadow та transition для створення візуальної симуляції світіння світлодіода.
